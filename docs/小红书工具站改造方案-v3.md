# 小红书工具站改造方案 v3

- 版本：v3.0
- 日期：2026-10-30
- 目标：把现有小红书相关工具连成可信、适合手机使用的内容工作流；优先验证用户是否得到实际帮助，再决定留存、获客和收费投入。
- 依据：线上首页、选题页、文案页的浏览；仓库中 `lib/xhs/`、`lib/aiwei/`、`lib/analytics/`、现有工具与额度实现；v1/v2 方案及其评审。

## 0. 决策摘要

**产品定位：一人造物中的小红书创作工作流，帮助个人创作者把手上的素材变成经过检查、可发布、可复盘的内容。**

近期不做全面“运营平台”，也不把首页押注在单一入口。改造按四个原则执行：

1. **用户任务优先**：从“我手里有什么 / 我想完成什么”进入，而不是要求先理解工具目录。
2. **规则检查只做辅助**：扫描结果不能承诺安全、收录、流量或规避限流。
3. **成本与质量一起看**：不因“多给次数”来代替质量验证；先算真实成本，再调额度。
4. **最小可验证改造**：先上线工作流入口和移动端体验，用行为、用户反馈和成本共同判断是否继续。

### v3 相对 v2 的关键改动

- 首页采用“粘贴/输入素材 + 其他任务入口”的组合，不以单个粘贴框取代所有入口。
- “发布前体检”改名为“发布前检查”，明确只是文本辅助检查，不等于平台审核或效果预测。
- 删除“首评埋关键词”“回复前五条”“30 分钟数据不佳就改封面标题”等无可靠依据的操作建议。
- 40% 粘贴率不再作为硬验收线；用多个事件、用户任务测试和样本量解释结果。
- 不把提高 AI 额度列为默认动作；先核算单次成本、重试和有效采用率。
- 自动续上改为用户可控的本地草稿，有说明、保留期限、清空和关闭选项。
- 复盘不依赖先培养用户点静态清单；通过小规模任务测试验证用户是否愿意记录数据。

## 1. 当前产品基础与判断

### 1.1 已有能力

- 首页已有去 AI 味、选题、文案、AI 味检测、长文图卡等工具。
- `ai-flavor` 使用本地规则；`humanize`、`xhs-copy`、`xhs-topics` 调用 AI 服务。
- `lib/xhs/words.ts`、`lib/xhs/units.ts`、`lib/aiwei/rules/` 已有可复用规则资产。
- 小红书相关 AI 工具目前匿名每日额度为 3 次，登录用户每日 20 次（见 `lib/xhs/quota.ts`）；规则检测不占此 AI 额度。
- 已有浏览器本地草稿实现（长文图卡）；选题与文案的工具间交接使用 `sessionStorage`。
- 埋点目前记录 `open / run / done / take` 等行为及匿名访客日集合，可用于方向性观察；上线时间短，现阶段数据可能很稀疏。

### 1.2 已观察到的产品问题

- 品牌表达是“一人造物”通用工具集合，小红书创作路径没有独立的任务入口。
- 选题和文案页面各自可用，但前后输入需要交接，用户完成一次任务后缺少明确下一步。
- 工具说明中部分平台机制使用确定性措辞，例如标题关键词位置与权重的关系；需要校准其证据强度。
- 移动端是主要使用场景，但应从实际页面和真实设备任务流验收，不能只把“响应式”视为完成。

### 1.3 需要先核对而非假定的事

- 小红书工具在全站流量中的实际占比和各工具的使用分布。
- AI 每日真实调用量、失败重试量、供应商账单和单次有效结果成本。
- 埋点是否完整、匿名访客标识在移动端和跨日场景是否稳定。
- 线上登录、额度和部署配置是否与仓库当前代码一致。

以上在半天内核对即可；不对个位数样本做趋势结论。

## 2. 产品定位与用户任务

### 2.1 首阶段服务对象

聚焦个人创作者和轻量内容运营者：有主题、原稿、素材或 AI 初稿，需要打磨、检查、排版并发布的人。

暂不以 MCN、品牌团队和多账号批量运营作为首要对象。这些用户需要协作权限、项目管理、授权数据和团队流程，超出当前轻工具的验证范围。

### 2.2 主要任务

1. **我有一段文字，想检查并修改。**
2. **我有素材或主题，想形成一篇笔记。**
3. **我想把长文整理成图卡。**
4. **我想找下一个选题。**
5. **我想复盘已发布内容。**

暂不把“通过小红书赚钱”作为首页任务入口：这是长期目标，不是一个能即时交付的具体动作。

### 2.3 定位表达

推荐文案：

> **把手上的素材，整理成更清楚的小红书内容。**
> 选题、文案、发布前检查和图文排版；平台表现由你在站内核实。

可继续保留「一人造物」母品牌。是否将小红书工具做成单独子品牌，等其流量和使用占比明确后再决定。

## 3. 首页与产品结构

### 3.1 首页采用“双入口”

主区域给有现成素材的人一个快速入口，同时提供清楚的任务快捷入口，避免把“所有访问者都有稿要粘贴”当作事实。

**主区：**

- 标题：把手上的素材，整理成更清楚的小红书内容。
- 多行输入框：粘贴草稿、素材或 AI 初稿。
- 主按钮：先做本地检查。
- 清楚提示：本地检查不会上传文字；选择 AI 改写时会把所需文本发送到 AI 服务处理。

**次级任务入口：**

- 我还没有选题 → 选题与验证
- 我有主题和素材 → 文案起草
- 我要整理成长图 → 长文图卡
- 我已发布内容 → 复盘记录（验证阶段后开放）

输入框不能自动触发 AI 请求。先在本地检查并展示结果，用户主动选择改写或生成时才调用 AI。

### 3.2 主流程

```text
粘贴已有文字 / 选择任务入口
  → 本地文本检查，或输入主题与真实素材
  → 用户查看结果并决定下一步
  → 可选：AI 改写 / 选题起草 / 图卡排版
  → 用户编辑、复制或导出
  → 可选：本地保存草稿或手动记录发布表现
```

任一步骤都能跳过。不要将“检查完必须改写”作为默认路径，也不要求用户建立账号档案。

## 4. 核心能力设计

### 4.1 发布前检查（候选核心入口）

把规则检查整合为一个入口是可行方向，但不能把多种检查压成一个“安全分数”。建议在同一页分组展示：

- **文字表达提示**：现有 AI 味规则命中句及其解释。
- **需人工核实的用词**：规则词表命中；注明是词表提示，不等于平台判违规。
- **格式与长度**：字符/单位统计、标签统计等确定性计算，并说明本工具采用的计算口径。
- **编辑建议**：仅在用户主动点击后调用 AI；展示原文与建议稿差异。

结果用“提示 / 建议核实 / 格式超出本工具设定”等具体状态，不使用“发出去会怎样”“零风险”“不会限流”等结果承诺。AI 味检测不应被描述为准确识别 AI 来源或判断平台能否识别。

### 4.2 选题与验证

- 保留现有按人群、场景和动机拆分选题的思路。
- 可选输入赛道、目标受众、账号阶段和内容目标，不强迫用户填写档案。
- 每个选题输出“需求假设、差异化角度、所需真实素材、站内验证词/问题”。
- 用户自行在小红书站内搜索并标记“值得做 / 换角度 / 暂缓”。
- 结果提供“带入文案起草”，自动交接已填主题和素材。
- 不展示无来源的热度、竞争度、搜索量或爆款概率。

### 4.3 文案起草与改写

- 真实素材优先；未提供经历和数据时，不替用户编造经历、结果、评价或数字。
- 生成结果标注“草稿，请核对事实与个人体验”，提供局部编辑和版本对比。
- 标题候选展示表达角度与适用情境，不声称某标题结构必然带来搜索或推荐流量。
- 标题长度、正文长度等仅作为工具校验口径；平台限制如有官方来源再明确引用。
- AI 改写属于独立的、有成本的动作，需由用户主动触发。

### 4.4 长文图卡

- 保留现有本地排版和导出能力。
- 从检查/文案页带入内容，避免重复粘贴。
- 导出前提供事实、授权素材、隐私信息和文题一致的自查提醒。
- 分享署名/水印应可选，不默认在用户内容中植入推广。

### 4.5 发布后复盘（先做可选原型）

不先做“30 分钟清单习惯钩子”。先通过访谈/任务测试确认目标用户是否愿意记录以及实际能从创作者中心取得哪些指标，再做最小版本。

最小复盘表允许跳过字段，记录：发布日期、内容类型、曝光/阅读等用户实际可见指标、点赞/收藏/评论/关注变化、观察周期、用户自己的结论。每个指标都显示来源和分母；拿不到的数据不要求填写。

输出用“观察 / 可能解释 / 下一次可验证的调整”格式。诊断是实验建议，不是算法结论。

## 5. 平台规则、行业经验与产品假设

三档分类保留，但要设置可执行的证据标准：

| 类别 | 展示方式 | 维护要求 |
|---|---|---|
| 平台规则 | 直接说明适用规则并链接官方页面 | 记录来源、适用范围、最后核对日期；规则变化后更新 |
| 行业经验 | 明确标注“运营经验”，描述适用场景和限制 | 不写成平台算法事实；能给出观察依据或测试方法 |
| 本工具假设 | 明确标注“待验证”，给出用户可执行的验证方法 | 不用百分比、权重或确定性承诺伪装成数据 |

例如，“核心词放标题前段”可作为标题可读性/搜索意图匹配的测试建议，但不能断言“前 6 个字权重最高”。“评论权重高于点赞”若无可验证来源和清楚的适用范围，不应以经验共识包装成确定规则。

小红书社区公约强调原创和真实分享、核实存疑信息、AI 辅助创作标明，以及避免夸张猎奇标题。产品应把这些用于发布前自查，不应把不透明的推荐机制写成已知规则。[小红书社区公约 2.0](https://pgy.xiaohongshu.com/help/detail?id=1eda0a065f92647735efb60001b704d2&userType=4)

商业合作内容和普通个人分享适用的规则可能不同；引用商业合作审核规范时，应标明适用场景，不能推广为所有普通笔记的统一规则。[蒲公英内容审核规范](https://pgy.xiaohongshu.com/help/detail?id=6495c527d1eedeeb48fb18b1f875650e&userType=4)

## 6. 成本、额度与隐私

### 6.1 先算清实际成本

半天核对：各 AI 接口调用量、输入/输出 token 或供应商账单、平均/高分位单次成本、失败重试比例、成功输出后的复制/采用行为、全站预算和限流触发情况。

统一报告：

- 每日 AI 总成本；
- 各工具成本与有效完成数；
- 每次成功生成成本、每次被采用结果成本；
- 重试和异常流量成本。

没有账单或模型用量记录时，不用“几厘一次”作为额度调整依据。

### 6.2 额度策略

- 规则扫描不调用 AI，保持无需登录、无 AI 次数扣减。
- 当前 AI 额度先不调整，直到完成成本核算和结果质量检查。
- 用小流量或短周期测试更高额度，并设置总预算、单 IP 限流、并发保护和异常告警。
- 评估额度时同时看用户完成率、结果采用率和成本，不单看生成次数。
- 长文图卡 AI 排版与小红书 AI 工具使用成本口径不同；先统一报表口径，确认有必要后再统一产品额度规则。

### 6.3 本地草稿

本地自动续上可作为低成本能力，但要由用户可控：

- 首次保存时说明正文保存在当前浏览器设备；
- 提供“继续上次”“清空草稿”“关闭自动保存”；
- 展示最近保存时间，避免旧稿被误认为当前稿；
- 设定保留期限，避免长期保存无提示；
- 跨工具交接保留显式确认，避免旧内容覆盖新输入。

选择 AI 改写时，明确说明所需文本会发送到 AI 服务端处理。规则检查本身不上传正文。隐私提示应出现在动作发生处，而不是只放在页脚。

## 7. 移动端与交互验收

手机端作为阶段 1 验收条件。至少用真实移动视口走完：打开首页、粘贴/输入、检查结果定位、主动选择改写、编辑、复制、带入图卡、导出。

验收关注：

- 输入区、主操作和结果定位在窄屏上可用，不出现横向溢出；
- 键盘弹出时输入和结果操作不被遮挡；
- 长结果可分段查看和编辑；
- 复制失败有可执行的回退方法；
- AI 请求中、失败、超时、额度不足和本地保存失败状态清楚；
- 粘贴文本不会自动发送到 AI。

## 8. 事件与验证方法

### 8.1 埋点补充

在现有 `open / run / done / take` 基础上按需增加：

- `input_started`：输入框出现有效内容；不记录正文；
- `check_done`：本地检查完成；
- `rewrite_requested`：用户主动发起 AI 改写；
- `handoff`：进入选题、文案或图卡等下一步；
- `draft_saved` / `draft_resumed`：用户主动保存或恢复；
- `feedback_submitted`：用户对结果是否有帮助做反馈。

区分粘贴与键入仅在浏览器事件允许且不收集正文的前提下进行；不得把“检测到粘贴”当作价值指标。

### 8.2 核心判断面板

- 入口启动率：有效输入或任务启动的独立访客 / 首页独立访客。
- 检查完成率：完成本地检查的访客 / 启动检查的访客。
- 结果采用率：复制、保存、继续编辑或交接的访客 / 检查完成访客。
- AI 采用效率：AI 成功结果后被复制/保存/编辑的比例及单次成本。
- 工作流完成率：从启动到复制/导出的访客比例。
- 回访：在明确的匿名访客口径、窗口和分母下报告 7 日/30 日回访人数与比例。
- 质量反馈：有帮助/无帮助和开放反馈；展示样本数。

低样本阶段以用户任务测试和个别反馈解释数据，不将单一比例作为自动成败线。阶段报告同时写人数、分母、时间范围和埋点覆盖情况。

## 9. 分阶段计划

### 阶段 0：半天基线核查

1. 确认埋点事件能写入、匿名访客集合能工作。
2. 确认 Redis 与 AI 配置状态、线上与仓库额度规则一致。
3. 核对最近可用账单/调用量，估算当前每日成本和重试占比。
4. 用手机视口快速走查现有核心路径，列出阻断问题。

产出：一页基线记录。此阶段不做低样本趋势推断。

### 阶段 1：1–2 周，建立可用的核心路径

1. 首页上线组合入口：素材检查主区 + 选题/起草/图卡快捷入口。
2. 建立本地检查结果分组，规则检查和 AI 改写清楚分开。
3. 选题页到文案页传递主题、目标和素材；结果页能继续到图卡。
4. 修订未经证实的平台机制断言，增加结果反馈。
5. 完成移动端核心任务验收。
6. 新增最少的行为事件，不采集粘贴正文。
7. AI 额度暂不提到 10 次；按阶段 0 成本和异常保护评估。

验收看板：输入启动、检查完成、结果采用、工作流完成、移动端阻断缺陷、日成本。上线前设定风险边界，但不以“粘贴率 40%”作单点门槛。

### 阶段 2：2–4 周，验证回访价值

1. 上线可关闭、可清空、有限期的本地草稿续上。
2. 观察用户是否主动保存/恢复，是否跨工具继续创作。
3. 对目标创作者做少量任务测试，确认发布后复盘数据的可取得性和记录意愿。
4. 如反馈明确，再做最小可选复盘，不先上线固定的“30 分钟改封面/埋词”清单。

进入条件：核心流程在移动端可用，且有足够的实际用户反馈指出一个重复出现的回访需求。无需等到达到某个虚构的留存百分比。

### 阶段 3：获客实验与商业化判断

- 自营内容账号作为一个获客实验，而非零成本必然渠道；记录内容主题、访问来源和有效完成。
- 内容展示真实创作过程与工具边界，不保证涨粉/流量，不引导违规站外交易或诱导互动。
- SEO 逐页做高意图工具和教程，验证搜索访问能否完成任务。
- 有稳定的重复使用和清晰的高成本价值功能后，再测试专业版/付费；早期可做访谈或意愿调查，不必在站内大规模搭建付费系统。
- 暂不做自动抓取、自动发布、批量互动或要求用户提供小红书登录态的功能。

## 10. 近期执行顺序

1. 核对线上与仓库功能、埋点和 AI 真实成本。
2. 先把当前工具页的手机核心流程走通，记录具体阻断点。
3. 改首页为素材入口加任务快捷入口，不先移除现有工具目录。
4. 合并检查体验，但保留“表达提示 / 词表提示 / 格式校验”各自含义。
5. 打通选题 → 文案 → 图卡的上下文交接。
6. 额度保持现状，成本核算后再讨论调整。
7. 本地草稿加入保存提示、关闭、清空和过期设计后再上线。
8. 用真实任务测试决定是否做发布后复盘与获客内容实验。

## 11. 明确不做

- 不把“体检”描述成平台审核、限流预测或发布安全保证。
- 不教用户为了影响分发而“首评埋关键词”“批量回复”或按半小时数据改标题封面。
- 不伪造热度、搜索量、竞争度、流量权重和爆款概率。
- 不将单个 AI 味分数作为真实性判断。
- 不在未核算成本前提高 AI 额度。
- 不默认长期保存粘贴正文或将其上传。
- 不用低样本百分比决定产品成败。
- 不在用户需求和数据授权未明确前开发抓取、自动发布、自动互动或团队分析。

## 12. 方案风险与证伪点

| 判断 | 证伪信号 | 应对 |
|---|---|---|
| 有现成素材的用户需要发布前检查 | 用户进入后很少启动检查，访谈也没有对应痛点 | 保留其为工具页，不再作为首页主区；提升选题/图卡等入口 |
| 检查结果对创作者有帮助 | 完成检查但无人复制、修订、反馈有帮助 | 调整规则解释和误报，不以增加规则数量解决 |
| 工具间连续流程有价值 | 用户经常中断在交接处或直接复制离开 | 先修交接摩擦，不强制做“工作区”概念 |
| 本地草稿带来回访 | 保存/恢复极少，用户担心隐私 | 关闭默认自动保存，保留手动保存或仅当前会话交接 |
| 发布后复盘值得做 | 用户拿不到数据或不愿录入 | 停止表单开发，改用访谈/模板下载等更轻方案 |
| 自营内容能获客 | 内容有浏览但无有效工具启动 | 换主题/承接页；评估其他渠道，不归因于单纯曝光 |
