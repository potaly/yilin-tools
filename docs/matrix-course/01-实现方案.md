# 全平台自媒体矩阵 — 实现方案分析

- 版本：v1.0（2026-10-22）
- 用途：作为培训课程的底层方案，先把「能自动到哪一步、哪一步必须人工」说清楚，再谈教法
- 配套：[02-课程大纲.md](02-课程大纲.md) · [03-提示词与模板.md](03-提示词与模板.md)

---

## 1. 先把问题拆对

大部分人把「矩阵」理解成「一篇稿子发到五个平台」，于是做出来的东西两周就死。真实的工作量分布是：

| 环节 | 占时间 | 能不能让 AI 干 |
|---|---|---|
| 选题 | 20% | 能，但要喂给它「数据 + 你的赛道定位」，否则全是正确的废话 |
| 写母稿 | 15% | 能，质量取决于素材而不是提示词 |
| **平台适配**（改写/拆条/标题/封面） | **35%** | **能，而且是自动化收益最大的一段** |
| 视觉（图卡、封面、剪辑） | 20% | 半自动：模板化之后能批量 |
| **发布上传** | **10%** | **大部分平台不能，这是方案里唯一的硬约束** |
| 复盘回流 | 不做，所以永远不长 | 能，前提是你愿意每天填一张表 |

**第一性结论：矩阵不是「写得快」，是「一份内容资产 → N 个平台形态」的转换效率，加上一条能长期跑的流水线。**
所以方案的重心放在「适配」和「流程纪律」上，不要一开始就追求全自动发布。

## 2. 平台能力矩阵（自动化上限）

这是整套方案的地基。每个平台能自动到哪一步，决定了工具该做什么、课程该教什么。

| 平台 | 内容形态 | 官方发布 API | 现实可行的自动化 | 自动化上限 |
|---|---|---|---|---|
| **微信公众号** | 图文长文 | **有**：`POST /cgi-bin/draft/add` 存草稿、`freepublish/submit` 发布 | 脚本把 Markdown 转 HTML → 上传封面拿永久 `media_id` → 推进草稿箱 | **到草稿箱，人工点发布**（强烈建议停在这一步） |
| **小红书** | 图文笔记 / 短视频 | 实际上**没有**面向个人创作者的公开发布接口（开放平台偏品牌方、服务商、白名单） | 生成「图卡包 + 标题 + 正文 + 话题」，在创作服务平台（电脑网页）粘贴 + 定时发布 | **到「一键粘贴即可发」的素材包**，发布动作人工 |
| **抖音 / 快手** | 短视频 | **有**，但要先创建应用、过审、拿到用户 OAuth 授权（含 `video.create` 这类发布权限） | 个人号大概率申不下来；先人工上传，量大了再评估申请 | **到成片 + 标题 + 话题 + 封面**，上传人工 |
| **视频号** | 短视频 | 个人创作者**没有** | 视频号助手（电脑网页）人工上传 | 同上 |
| **朋友圈** | 图文 | **完全没有**，个人微信自动化属于违规高风险区 | 工具只做「文案 + 配图包 + 一键复制」 | **永远人工**。企业微信的「客户朋友圈」另算，有接口 |
| 知乎 / B 站 / 头条 | 长文 / 视频 | 各不相同，按需单独评估 | 第一期不要碰，先把三个主力平台跑顺 | — |

### 2.1 由此得到的三条硬规矩

1. **「全自动发布」是伪需求**，追它会把方案推向浏览器自动化（Playwright 模拟登录、存 cookie），结果是封号风险 + 每次平台改版就坏。
2. 正确的目标形态是 **「自动到草稿 / 素材包 + 人工一键确认」**。人工那一下只要 30 秒，但它同时解决了合规审核、风格把关、平台风控三件事。
3. 公众号是唯一值得做深度自动化的平台（有正规接口）。它也因此是课程里最适合当「自动化成就感」的演示环节。

> 公众号草稿接口的几个坑（写脚本和讲课都会踩）：只能服务器端调用、`access_token` 要缓存、服务器 IP 要进白名单、封面必须是**永久素材** `media_id`、`content` 字段有大小上限且正文里的图片必须先走「图文消息内图片上传」换成微信域名的 URL、`title` 32 字以内。

## 3. 三条实现路线（按投入从小到大）

### 路线 A：纯 Agent 工作流（0 开发，1–2 天能跑）—— 课程主线

把电脑上的一个文件夹当作流水线，WorkBuddy 当作操作这条流水线的「同事」。

```
~/matrix/
  00-选题池/        topic-YYYYMMDD-关键词.md     （状态写在 frontmatter）
  01-素材/          按选题建子目录，截图/链接/数据/录音
  02-母稿/          master-<topic>.md            （唯一真相，1500–2500 字）
  03-平台稿/
      公众号/       oa-<topic>.md
      小红书/       xhs-<topic>.md（标题 + 正文 + 话题 + 图卡文案）
      口播/         script-<topic>.md（分镜表）
      朋友圈/       moments-<topic>.md
  04-成品/          图卡 PNG、封面、成片
  05-已发布/        发布记录 + 数据回填表 publish-log.csv
  _规范/            选题标准.md、语气词典.md、禁用词.md、检查清单.md
```

关键不是文件夹本身，而是：**目录结构 + 命名规范 + 每道工序的「完成定义」固定下来，Agent 才有可能接手。** 这是课程里最值钱的一节，比任何提示词都值钱。

工作方式：每道工序一张「任务卡」（见 `03-提示词与模板.md`），WorkBuddy 按卡执行，产出写回对应目录。定时任务负责每天早上的选题雷达和每晚的待发布清单。

### 路线 B：Agent + 少量脚本（1–2 周）

把路线 A 里每天都在重复、规则又固定的动作，用 Codex 写成命令行脚本，再交给 WorkBuddy 调用。优先级排序：

| 脚本 | 价值 | 难度 |
|---|---|---|
| `oa-draft` 公众号草稿推送（Markdown → HTML → 封面 → 草稿箱） | 高：唯一能真正省掉的重复劳动 | 中 |
| `cards` 批量生成图卡（复用本站 `lib/cards` 引擎） | 高：小红书每条都要 | 低 |
| `topics` 选题雷达（抓榜单/关键词 → 去重 → 打分 → 写入选题池） | 中：取决于数据源 | 中 |
| `log` 数据回流（手填或半自动回收阅读/点赞 → CSV → 周报） | 中：决定矩阵能不能迭代 | 低 |
| `lint` 发文前质检（禁用词、错别字、AI 标识、字数、话题数） | 高：挡事故 | 低 |

**判断规则（课程里要反复说的一句话）：一次性或低频的活，直接让 WorkBuddy 干；每天重复且规则固定的活，让 Codex 写成脚本，再让 WorkBuddy 调脚本。** 让 Agent 每天即兴发挥同一件事，等于每天重新赌一次质量。

### 路线 C：产品化（做成站内工具，2–6 周）

即「矩阵工作台」。本站（Next.js 14 + Upstash Redis + Vercel）已经现成的部分：

- `lib/cards/*` 整套排版引擎（解析 → 断行 → 分页 → Canvas 绘制 → PNG/ZIP/PDF 导出）＋ 模板配色体系
- `lib/ai/*` OpenAI 兼容调用、长文分块、结构校验、原文覆盖率
- 账户 / 算力 / 限流 / 后台用量统计，都能直接复用

必须新增、且会改变架构的部分（这是要不要做的真正成本）：

| 新增 | 为什么是硬成本 |
|---|---|
| 内容库持久化（选题池 / 母稿 / 平台稿 / 版本） | Redis 当 KV 够用，但要列表查询、筛选、全文检索就该上 Postgres（Neon/Supabase） |
| 多平台改写 + 质检的服务端编排 | 一次请求打 5 个平台的改写，60s 函数时限不够，要任务队列（Vercel Queues / Cron + 状态机） |
| 公众号接入 | 要服务器 IP 白名单 → Vercel 无固定出口 IP，得挂一个固定 IP 的代理或小服务器；还要素材上传、`access_token` 集中缓存 |
| 浏览器自动化（如果真要做小红书自动发） | 不能跑在 Serverless 上，要常驻机器；且有封号风险。**建议直接不做** |
| 多账号矩阵的权限与隔离 | 一个号一套凭据，密钥存储和审计要重新设计 |

**结论：建议分两步。**
第一步做「**矩阵内容工作台**」——纯内容生产，不碰发布：选题池 + 母稿 + 一键生成五平台适配稿 + 图卡批量导出 + 发文前质检清单。这一步和现有工具同构，加法而非改造，一两周能上，而且正好是课程的配套工具（学员用它交作业）。
第二步再评估「**公众号草稿推送**」是否值得为它引入固定 IP 服务。其它平台的「一键发布」不要做。

## 4. 内容流水线：六道工序与完成定义

课程和工具都按这六道工序组织。每道工序必须有「验收标准」，否则 Agent 产出无法判定好坏。

| # | 工序 | 输入 | 输出 | 完成定义（验收标准） |
|---|---|---|---|---|
| 1 | 选题 | 榜单/评论/后台搜索词/同行 | 选题卡：一句话痛点 + 目标人群 + 预期形态 + 来源证据 | 能用一句话说出「谁、在什么场景下、为什么会点开」；有数据或原文链接作证据 |
| 2 | 母稿 | 选题卡 + 素材 | 1500–2500 字母稿，含观点、3 个以上具体案例/数据 | 每个论点有具体例子；删掉所有「随着…的发展」式废话 |
| 3 | 平台适配 | 母稿 | 公众号稿 / 小红书图文 / 口播脚本 / 朋友圈文案 | 四份稿的**开头完全不同**；小红书不超 1000 字、口播稿前 3 秒有钩子 |
| 4 | 视觉 | 平台稿 | 图卡组、封面、成片 | 封面 3 秒内能读完主标题；手机上实际看过一遍 |
| 5 | 发布 | 成品 | 各平台草稿/已发 + 发布记录 | 过完质检清单（禁用词、AI 标识、话题数、@、评论区首评） |
| 6 | 复盘 | 发布记录 | 数据回填 + 周报 | 每周能说出「哪条超均值 2 倍、为什么」，并把结论写回 `_规范/选题标准.md` |

**最容易塌的是第 6 道。**没有第 6 道，前五道就是在盲发；课程必须把它做成强制作业。

## 5. 爆款视频「复刻」的方法与边界

### 5.1 先划清边界（课程第一页就要讲）

- **可以学的**：结构、节奏、钩子写法、信息密度、选题角度、封面与标题的句式。
- **不可以搬的**：画面素材、原声口播、BGM 整段、字幕文件、他人出镜。搬运既是侵权，也会被平台判重限流。
- **AI 生成的画面/配音必须标识**：《人工智能生成合成内容标识办法》自 2025 年 9 月 1 日起施行，要求显式标识（界面可感知的文字/声音/图形）与隐式标识（文件元数据），并且不得恶意删除、篡改、伪造、隐匿标识。实操上：用 AI 生成的画面或配音，发布时打开平台的「AI 生成」声明开关，并在文案里写明。

### 5.2 五步复刻法

1. **采集**：选同赛道近 30 天 20 条高播放，只记录链接 + 封面 + 标题 + 数据，不下载搬运。
2. **结构化拆解**：每条填一张拆解表（钩子句 / 0–3 秒画面 / 结构类型 / 每个信息点时长 / 情绪曲线 / 结尾 CTA / 评论区被顶起的那条）。20 条之后共性自己就浮出来了，这一步 AI 能批量帮你填，但**样本和链接得你给**。
3. **换壳**：取「结构 + 钩子句式」，把内容换成你自己的案例。产出 10 个候选选题，挑 3 个。
4. **成片**：口播稿 → 分镜表 → 素材（自拍 / 正版素材库 / AI 生成）→ 剪映（字幕、节奏卡点、封面）。模板化：同一账号固定一套字幕样式、片头 0.5 秒、封面版式，让「复刻」变成填空。
5. **发布与验证**：同一结构连发 3 条才能判断结构有效性，一条看不出任何东西。

### 5.3 哪里用 AI、哪里不要用

- 用：拆解表批量填写、换壳选题、口播稿初稿、标题 20 个候选、字幕纠错、封面文案。
- 不要用：决定赛道和人群（这是你的判断）、最终成片的「像不像人说话」（必须自己念一遍）、数据解读（AI 会编因果）。

## 6. WorkBuddy 与 Codex 的分工

| | WorkBuddy（腾讯的桌面 AI Agent，CodeBuddy 团队出品） | Codex（命令行编码 Agent） |
|---|---|---|
| 角色 | **跑流程的同事**：按任务卡执行、定时触发、多任务并行、通过 MCP 连外部服务、能从微信/Slack 等远程下指令 | **造工具的工匠**：写脚本、改这个网站、做工具页、补测试 |
| 适合 | 每天的选题雷达、母稿初稿、平台适配、待发清单、周报 | `oa-draft` / `cards` / `lint` 等脚本，站内「矩阵工作台」工具 |
| 不适合 | 每天即兴重做同一个规则固定的动作；碰账号凭据 | 日常内容生产（它不是为这个设计的） |

> 注：WorkBuddy 的具体功能（定时、MCP 可连哪些服务、专家角色、是否能接自备模型 Key）以你机器上安装的版本为准，课程录制前按实际界面过一遍，不要照搬网上的体验文。

落地顺序建议：**先用 WorkBuddy 手工跑通两周**（纯路线 A），把哪一步最痛、最耗时量化出来，再让 Codex 为那一步写脚本。反过来先写工具，十有八九写出用不上的功能。

## 7. 风险清单

| 风险 | 后果 | 对策 |
|---|---|---|
| 一稿多投、平台判重 | 限流、不推荐 | 每个平台开头/结构/标题必须不同；小红书与公众号不共用同一张封面 |
| AI 内容未标识 | 违规、下架 | 发布开关 + 文案声明，写进质检清单（2025-09-01 已施行） |
| 把账号 cookie 交给第三方自动发布工具 | 盗号、封号 | 不用来源不明的「一键全平台发布」工具；凭据只放本机或自有服务 |
| 医疗/金融/保健等限制类表述 | 封号、行政风险 | `_规范/禁用词.md` + 发文前脚本扫描 |
| 全自动发布导致事故稿上线 | 口碑、删文 | 流程强制停在「草稿 + 人工确认」 |
| 只发不复盘 | 三个月后放弃 | 周报作为课程强制作业，数据回填不填就不算结课 |

## 8. 成本量级（单人，每月）

| 项 | 量级 | 说明 |
|---|---|---|
| 模型调用 | 几十元 | 国产模型跑文字改写，每天 10 条内容量级，花不了多少 |
| 视频 AI（可选） | 100–500 元 | 生成画面/配音才需要，起步可以不用 |
| 工具订阅 | 0–200 元 | WorkBuddy / 剪映会员 / 素材库 |
| 固定 IP 小服务器（仅公众号 API 需要） | 20–60 元 | 走路线 B/C 第二步才需要 |
| **真正的成本是人力** | 每天 1.5–3 小时 | 流水线跑顺后的稳定投入；低于这个数矩阵不成立 |

## 9. 给这套方案的一句话总结

> 自媒体矩阵的技术含量不在「自动发布」，而在**把一份内容资产可靠地转换成 N 个平台的形态，并且每周用数据修正选题标准**。
> 工具只负责消灭重复劳动；判断、复核、发布那一下，留给人。
