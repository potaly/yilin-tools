# 小红书工具站改造方案

- 版本：v1.0
- 日期：2026-10-30
- 目标：把现有零散工具整合为一条可信、可复用的小红书创作工作流，并明确分阶段的产品与运营改造顺序。
- 依据：线上首页、「小红书选题」「小红书文案」页面的实际浏览；用户提供的另一模型方案；现有仓库 README 与需求文档。

## 1. 结论摘要

建议把产品定位为：**面向个人创作者和轻量运营者的小红书内容工作台，帮助用户完成选题验证、内容创作、素材排版和发布复盘。**

改造重点不是一次性补齐“选题、爆文、数据、商业化”所有模块，而是：

1. 保留当前工具的诚实边界、真实素材输入和本地处理优势。
2. 把「选题 → 文案 → 图卡 → 发布检查 → 复盘」串成一条可完成的工作流。
3. 将未经可靠依据支持的平台机制断言改成可验证的建议。
4. 先用低成本的本地草稿和用户自填复盘建立回访，再依据使用数据决定账号系统、数据接入和收费。

## 2. 现状观察

### 2.1 已看到的线上页面

- 首页品牌为「一人造物」，主张一个人用 AI 做工具，提供去 AI 味、选题、文案、AI 味检测、长文图卡等工具。
- 首页和工具页主打打开即用、无需注册；隐私说明称文字和图片默认在浏览器处理，除非用户主动使用 AI 排版。
- 「小红书选题」页明确说明不抓取小红书数据，并要求用户自行到搜索框验证；选题按人群与动机组织。
- 「小红书文案」页要求用户提供真实素材，区分搜索型与发现型，输出标题候选、正文和标签。
- 工具导航目前是并列入口。用户完成一个工具后，页面未呈现明显的下一步工作流入口。
- 文案页含有“核心关键词必须落在标题前 6 个字”“搜索权重最高”等较确定的平台机制表述，应核实依据或调整语气。

### 2.2 仓库提供的产品背景

仓库 README 显示产品目前以轻量工具箱为基础，首个工具是长文图卡；具备 AI 排版服务、限流、使用成本统计和可选登录/算力机制。现有实现可为本方案提供图卡生产环节，但线上功能、流量、留存、成本、登录与收费开关的实际状态，需要由部署和分析数据确认。

### 2.3 当前优势

- 不假装拥有平台实时数据，明确告诉用户要自行验证。
- 真实素材优先，降低生成内容凭空编造的概率。
- 无需注册即可开始，工具页门槛低。
- 本地处理与隐私说明具备信任价值。
- 已覆盖选题、文案、AI 文本处理和长文图卡等内容生产节点。

### 2.4 当前主要缺口

- 产品定位混合：母品牌是通用 AI 工具集合，小红书运营是其中一条功能线。
- 用户按工具名进入，而不是按要完成的任务进入。
- 选题结果与文案、图卡、发布、复盘之间缺少连续状态和交接。
- 缺少可积累的内容资产入口，例如草稿、选题清单、发布日历和复盘记录。
- 平台规则和内容风险信息需要有来源、更新时间、适用范围和不确定性提示。
- 暂无足够数据判断最有价值的用户群、核心工具、回访原因及付费意愿。

## 3. 借鉴另一模型方案：采纳、收敛与暂缓

| 建议 | 处理 | 原因 |
|---|---|---|
| 从工具集合转成解决用户任务的产品 | 采纳 | 有助于统一首页、导航、工具之间的下一步与增长路径。 |
| 首页按“我今天要解决什么”组织 | 采纳 | 新用户更容易找到入口；优先做轻量任务入口，不必立即重做整个品牌。 |
| 打通选题、创作、排版、复盘 | 采纳，作为核心方向 | 现有工具已覆盖部分环节，整合比盲目加工具更有机会形成回访。 |
| 建立选题日历、收藏、历史和发布记录 | 分阶段采纳 | 可提升持续使用，但先做本地保存或轻量草稿验证需求，避免过早引入账号和云端成本。 |
| 爆文/竞品链接分析 | 暂缓 | 要先确认数据获取方式、稳定性、授权与维护成本。可先做用户粘贴素材后的结构分析，不承诺自动获取完整平台数据。 |
| 账号诊断、竞争度、搜索量、爆款概率 | 暂缓或限制为假设 | 若无可靠数据，容易把模型推测包装成客观指标，损害信任。先支持用户自填数据并明确计算口径。 |
| 先做五大工具分类、完整工作台布局 | 收敛 | 目前产品规模不需要复杂后台式界面。优先做单篇内容工作区与清楚的任务导航。 |
| SEO 页面矩阵 | 采纳原则，逐页验证 | 每页应独立解决真实问题，避免批量生成近似、低价值落地页。 |
| 免费版/专业版/团队版 | 作为待验证商业假设 | 当前缺少用户留存与付费数据，不应先投入完整会员、团队权限或额度体系。 |
| 视觉使用小红书暖红色、统一卡片组件 | 选择性采纳 | 可形成一致性，但视觉改版优先级低于定位、工作流和信任；也不应让界面看起来像官方产品。 |
| 10 秒找到工具、1 分钟得到结果 | 作为体验目标，不作为已验证承诺 | 可作为设计目标，通过任务完成率与首个结果时间验证。 |

## 4. 产品定位与用户范围

### 4.1 建议定位

**一人造物的小红书创作工作台：用真实素材做内容，用清晰步骤完成从选题到复盘。**

母品牌可以继续保留「一人造物」。在首页增加小红书创作入口或独立专题页，让有小红书任务的用户快速进入；是否将其升级为独立子品牌，应依据流量和用户使用占比决定。

### 4.2 优先服务人群

首阶段聚焦：

- 正在稳定更新的小红书个人创作者；
- 一人或小团队负责内容的轻量运营者；
- 需要图文内容整理、文案起草与发布复盘的知识/生活方式创作者。

暂不把 MCN、品牌投放团队、多账号批量运营作为首要用户，因为其协作、数据、权限和商业分析需求会显著扩大产品范围。

### 4.3 核心用户任务

1. 我有一个方向，但不知道这周写什么。
2. 我有想法和素材，需要变成像自己说话的笔记。
3. 我有长文，需要整理成适合手机阅读的图卡。
4. 我发过内容，想知道下次具体改什么。

## 5. 产品信息架构与关键流程

### 5.1 建议导航

- **开始创作**：单篇笔记工作流入口。
- **选题与验证**：选题矩阵、搜索验证清单。
- **文案与检查**：标题、正文、标签、AI 味与风险自查。
- **图文排版**：长文图卡、封面与导出。
- **计划与复盘**：内容日历、发布记录、数据复盘。
- **工具箱**：保留其他通用工具，避免它们挤占小红书主流程。

### 5.2 核心工作流

```text
确定内容目标
  → 输入赛道、受众、主题和真实素材
  → 生成选题候选与验证问题
  → 用户在小红书站内验证并记录判断
  → 选择选题生成多个文案方向
  → 编辑正文、检查表达与风险提示
  → 排成图卡或复制发布素材
  → 用户记录发布数据和观察
  → 形成下一轮选题建议
```

每一步都要允许跳过或返回修改；工具不能让用户误以为平台数据已经自动验证。

### 5.3 单篇内容工作区

以一篇笔记为一个项目容器，保存：

- 主题、赛道、受众、内容目标；
- 选题候选和人工验证记录；
- 素材来源、事实与个人体验；
- 标题候选、正文草稿和标签；
- 图卡版本和导出状态；
- 发布日期、用户自填数据与复盘结论。

MVP 可先在浏览器本地保存。若数据需要跨设备同步，再评估账户系统、隐私说明、删除/导出能力与服务端存储。

## 6. 页面改造方案

### 6.1 首页

**首屏目标：让用户立即知道这不是平台数据分析服务，而是一套创作和运营工作流。**

建议结构：

1. 主标题：**从选题到复盘，做好每一篇小红书内容**。
2. 副标题：**用真实素材完成选题验证、文案打磨和图文排版；平台数据由你在站内确认或手动记录。**
3. 主按钮：**开始做一篇笔记**；次入口：**先找选题**。
4. 任务入口：我不知道发什么 / 我有素材要写 / 我要排成长图 / 我想复盘已发布内容。
5. 展示三步流程和一个真实示例，解释输入、输出与数据边界。
6. 下方保留其他「一人造物」工具，作为次级区块。

避免声称能保证流量、打造爆款或准确预测平台推荐。

### 6.2 选题页

- 保留人群/动机维度与诚实说明。
- 输入增加可选字段：赛道、账号阶段、目标、受众、用户已有素材。
- 候选结果补充：需求假设、可写角度、需要的真实证据、站内验证关键词/问题。
- 增加验证记录：搜索日期、观察到的内容模式、用户结论、是否立项。
- 每条候选提供「用这个选题写文案」，把上下文传入工作区。
- 不显示伪造的搜索量、竞争度、热度或爆款概率。

### 6.3 文案页

- 从选题页接收主题、受众、目标和验证备注。
- 真实素材设为推荐输入；没有素材时明确标记为“灵感草稿”，不自动编造经历、效果、评价或数字。
- 标题候选给出写法差异和适用场景，但把流量结果表述为假设而非保证。
- 提供逐段编辑、版本对比、复制单项、保存草稿和继续排版。
- 将“违规词/限流”类绝对判断改为“需要核实的风险提示”，给出提示原因与人工检查建议。
- 每项平台规则标注来源、最后核对时间、适用范围；没有把握的机制性信息不做硬编码结论。

### 6.4 长文图卡

- 作为工作流里的内容呈现步骤，而非孤立工具。
- 支持从笔记草稿带入内容，提供标题/封面/正文的轻量预览。
- 保留现有模板、导出和浏览器本地处理优势。
- 在导出前提供检查项：文字是否准确、事实是否核对、图片和素材是否有使用权。

### 6.5 复盘页

- MVP 支持手动录入曝光/阅读、赞、藏、评、关注等用户实际可取得的数据；字段可选，说明统计时间点。
- 展示公式、样本量与口径；例如互动率必须明确分母，不能只给一个无解释的百分比。
- 先做同账号自身内容的对比和趋势，不轻易跨账号、跨赛道下结论。
- 每份报告按“观察到什么 / 可能原因 / 下一次实验 / 如何判断”输出。
- 数据不足时直接说明不足，不生成确定性诊断。

## 7. 信任、内容质量与数据边界

### 7.1 事实与建议分层

所有输出建议区分：

- 用户明确提供的事实；
- 工具做的文本处理或计算；
- AI 推断与创意建议；
- 需要用户在小红书或创作者中心验证的信息。

### 7.2 平台规则维护

- 平台政策、商业合作和 AI 内容标识等信息采用官方来源，并记录链接、核实日期与适用范围。
- 将“平台规则”“行业经验”“本工具假设”用不同标签展示。
- 不承诺规避审核、避免限流或必然获得推荐。
- 第三方数据采集、链接解析、自动发布或自动互动功能立项前，先确认数据来源、授权方式、规则与维护成本。

### 7.3 隐私和用户素材

- 明确哪些功能本地处理、哪些会调用 AI 服务端、发送哪些文本以及保留多久。
- AI 调用前用近输入框的位置说明数据流向；敏感素材提醒用户先脱敏。
- 本地草稿提供清空能力；若未来云端保存，提供删除与导出。
- 不把用户草稿用于训练或展示，除非产品另行清楚征求同意。

## 8. 增长与 SEO 方案

### 8.1 获客内容

优先围绕真实任务做内容：选题验证示例、真实素材如何变成笔记、长文图卡案例、发布后如何复盘。每篇教程都链接到对应的工具起点，避免只宣传“AI 很强”。

### 8.2 SEO 页面

逐步建设高意图工具页与教程页，例如标题构思、选题验证、图文排版、笔记复盘。每个页面都应有：目标用户、输入示例、输出示例、方法边界、相关下一步工具和常见问题。

先验证少量页面的搜索曝光和工具启动率，再扩展主题；不批量制造换词页面。

### 8.3 分享与回访

- 支持导出选题清单、图卡和复盘摘要；分享物本身要有用，不强制水印或广告。
- 提供可保存的草稿、验证清单和发布计划。
- 通过站内轻量反馈收集“结果是否有帮助”和“具体哪里不准”。
- 回访提醒、邮件或社群运营等功能需在用户主动选择后再做。

## 9. 商业化策略

先验证高频任务与重复价值，再测试收费。

可测试的顺序：

1. 免费核心流程，观察是否完成工作流和是否回访。
2. 对高成本或明显节省时间的能力做小规模付费实验，例如批量处理、更多项目、历史管理或进阶复盘。
3. 只有出现团队协作的真实需求后，再评估团队版。

建议不要先投入：复杂会员体系、团队权限、完整数据平台、低价广告位。若采用额度或订阅，必须先掌握单用户推理成本、服务成本、免费额度消耗和付费用户留存。

## 10. 分阶段实施路线

### 阶段 0：基线与产品核对（约 1 周）

- 核对线上功能与仓库实现是否一致。
- 整理已有流量来源、工具启动/完成、生成失败、复制/导出、重复访问和成本数据。
- 明确最常用工具、主要用户类型及当前用户反馈。
- 为关键页面设置事件和隐私合规的分析口径。

**产出：**现状基线表、用户任务优先级、核心漏斗。

### 阶段 1：定位与最小工作流（约 2–3 周）

- 首页增加“开始做一篇笔记”和按任务进入的路径。
- 选题结果可直接带入文案。
- 文案结果可保存/复制并进入长文图卡。
- 修订平台规则断言和风险提示文案。
- 增加生成中、失败、空结果、复制成功等完整状态。

**验收：**新用户能从入口走完选题/素材到可复制成稿或图卡导出的路径；不需要重复输入已提供的信息。

### 阶段 2：草稿与验证闭环（约 3–5 周）

- 本地项目/草稿保存、选题验证记录和发布计划。
- 增加用户自填的发布数据与轻量复盘。
- 移动端优化，优先检查输入、编辑、复制、图卡导出。

**验收：**用户可以离开页面后回来继续编辑；发布记录能关联到原选题和文案。

### 阶段 3：增长与收费实验（时间由数据决定）

- 依据有效搜索需求补充 SEO 页面和教程。
- 对高频且有明确价值的高级功能做小范围付费验证。
- 用支持工单、用户反馈、成本和留存结果决定是否扩展云同步、团队功能或外部数据能力。

## 11. 指标与埋点

先定义事件，不预设未经测量的目标值。

| 指标 | 建议口径 | 用途 |
|---|---|---|
| 工具启动率 | 进入工具页后开始有效输入的会话 / 工具页会话 | 判断入口与页面是否清楚 |
| 工作流完成率 | 开始创作后到复制、保存或导出的会话 / 开始创作会话 | 判断流程是否真正产出 |
| 步骤流失率 | 各步骤到下一步骤的转化 | 找出工作流断点 |
| 结果采用率 | 复制、保存、导出结果 / 成功生成结果 | 评估结果实用性 |
| 生成失败率 | 错误或超时请求 / 请求总数 | 监控可靠性和成本体验 |
| 7 日/30 日回访 | 按匿名或同意登录后的用户口径统计再次使用 | 判断是否有持续价值 |
| 用户自报满意度 | 对结果“有帮助”的评价比例及文本反馈 | 指导质量迭代 |
| 单次有效完成成本 | AI、基础设施等成本 / 完成工作流数 | 决定免费额度与收费边界 |
| SEO 到完成转化 | 搜索落地访问后完成核心动作的比例 | 判断内容获客是否有效 |

## 12. 明确暂不做的事项

- 不以工具数量作为产品进度目标。
- 不伪造实时热度、搜索量、竞争度和爆款概率。
- 不把账号诊断包装成确定的算法结论。
- 不在需求和授权未验证前开发自动抓取、自动发布、自动互动或批量运营。
- 不在留存与付费意愿未验证前建设复杂会员/团队系统。
