# Yilin 工具箱 — 需求文档

- 版本：v1.0（2026-10-21）
- 范围：工具站骨架 + 第一个工具「长文图卡」（含 AI 排版）
- 仓库：https://github.com/potaly/yilin-tools
- 来源：`yilin-tools-prompt.md`（原始需求）、`longform-cards.html`（已跑通的单文件原型）

---

## 1. 背景与目标

用户把一段格式混乱、密集成块的文字粘进来，网站把它排成手机比例的长文图卡（米白底、棕色字、大标题带高亮条），每页可存成 PNG。核心增量是 **AI 排版**：一键整理出大标题、小标题、合理分段、重点加粗，并按文字量给出合适的行距段距。

站点定位是一个**可持续扩展的工具箱**，长文图卡只是第一个工具。因此本期的首要工程目标是：加第二、第三个工具时，只需新增一个目录和一条注册项，首页与布局零改动。

### 成功判据

1. 同一段文字在新站点与原型里的分页结果基本一致（页数相同、断行位置一致）。
2. 用验收用例的「乱文本」点一次 AI 排版，产出有大标题、有小标题、段落 40–120 字、原文覆盖率 ≥ 95%。
3. 手机 390×844 下无横向滚动，能把图片存进相册。
4. 生产环境换 AI Key 不需要重新部署。

---

## 2. 范围

### 本期做

- 站点骨架：布局、首页工具卡片列表、工具注册表、深浅色主题。
- 长文图卡工具：编辑、预览、分页、Canvas 绘制、单页保存、打包下载。
- AI 排版：`POST /api/ai-format`，DeepSeek（OpenAI 兼容接口），分块、校验、限流。
- 快速清理：纯规则预处理，不调 AI。
- 配置管理：AI 配置可写进 Upstash Redis，改 Key 不重新部署。
- 单元测试（vitest）、README、Vercel 部署与自动部署。

### 本期不做（YAGNI）

- 用户账号、登录、历史记录云端存储（草稿只存 localStorage）。
- 自定义配色 / 字体 / 模板主题。
- 第二个工具的具体实现（只留扩展位）。
- AI 排版的流式输出（一次性返回即可，长文用分块并行压缩等待时间）。
- 服务端渲染图片（图片一律浏览器端 Canvas 生成，服务端不碰图）。

## 3. 站点结构与扩展约定

| 项 | 约定 |
|---|---|
| 站点名 | 「Yilin 工具箱」，定义在 `lib/site.ts`，全站引用，不硬编码 |
| 工具注册表 | `lib/site.ts` 导出 `TOOLS: ToolMeta[]`，字段 `slug / name / description / icon / status` |
| 工具页面 | `app/tools/<slug>/page.tsx`，一个工具一个目录 |
| 工具逻辑 | `lib/<domain>/`（如 `lib/cards/`），纯 TS，不依赖 React |
| 首页 | 遍历注册表渲染卡片网格，新增工具无需改首页代码 |

**新增一个工具的步骤（必须保持在 3 步以内）**：① 在 `lib/site.ts` 加一条注册项；② 建 `app/tools/<slug>/page.tsx`；③ 纯逻辑放 `lib/<domain>/` 并补单测。

## 4. 功能需求

### FR-1 编辑区

- 左编辑、右预览；`≥900px` 双栏，手机上下堆叠。**手机为主要场景**。
- 编辑语法：`#` 大标题、`##` 小标题、`**文字**` 加粗、每一行是一段；空行忽略。
- 语法提示条常驻显示（与原型一致）。
- 输入防抖 300ms 后重绘。
- 草稿存 `localStorage`（读写都 try/catch，隐私模式下不报错）。
- 首次打开即展示示例文字排好的卡片，不出现空白页。

### FR-2 操作按钮

| 按钮 | 行为 | 禁用条件 |
|---|---|---|
| AI 排版（主按钮） | 调 `/api/ai-format`，结果写回文本框并重绘 | 文本为空、请求进行中 |
| 快速清理 | 纯规则清理（见 FR-7），立即生效 | 文本为空 |
| 填入示例 | 覆盖为内置示例文字 | 无 |
| 清空 | 清空文本并聚焦 | 文本为空 |
| 撤销 | 回到 AI 排版 / 快速清理之前的文字 | 无快照 |

撤销只保留**一级快照**（最近一次 AI 排版或快速清理前的内容），不做完整编辑历史。

### FR-3 选项

| 选项 | 取值 | 默认 |
|---|---|---|
| 比例 | 3:5 长图（1080×1800）/ 3:4 小红书（1080×1440） | 3:5 |
| 密度 | 宽松 / 标准 / 紧凑 | 按字数自动（见 FR-5），用户手动切换后以用户为准 |
| 顶部信息 | 显示 /不显示「全文X字 ｜ 阅读需要X分钟」 | 显示 |

一旦用户手动动过密度，自动选档即失效（直到页面刷新或清空文本）。

### FR-4 预览与保存

- 显示总字数、总页数、每页缩略图与页码 `n / N`。
- 三种导出方式：

  | 操作 | 产物 | 用途 |
  |---|---|---|
  | 保存这页 | 单张 PNG（1080 宽） | 只要其中一页 |
  | 保存全部图片 | ZIP，内含每页 PNG（`jszip`） | 一次拿走所有图片 |
  | 保存 PDF | 一个 PDF，一页一张卡片，页面尺寸等于卡片像素尺寸（`jspdf`） | 打印、存档、发给别人连续翻阅 |

- `jszip` 与 `jspdf` 都用动态 `import()`，不进首屏 bundle。
- 桌面端：`<a download>` 直接下载。
- 移动端（`pointer: coarse` 且支持 `navigator.canShare({files})`）：走系统分享，可存相册或直接发微信；不支持时回落为下载，并提示「长按图片保存」。
- 文件名：`<标题前16字>-01.png`、`<标题前16字>.zip`、`<标题前16字>.pdf`，过滤 `\ / : * ? " < > |` 与空白、中文标点。
- 字体未就绪时不出图：绘制前 `document.fonts.load()` 按当前文字实际出现的字符加载 500/700/900 三个字重，最长等 5 秒；`loadingdone` 后再重绘一次。

### FR-5 密度预设

| 预设 | 正文字号/行高 | 段前距 | 小标题段前/段后 | 自动适用 |
|---|---|---|---|---|
| 宽松 `loose` | 38 / 78 | 52 | 120 / 34 | ≤ 800 字 |
| 标准 `standard` | 35 / 70 | 44 | 116 / 30 | 800–2500 字（等于原型） |
| 紧凑 `compact` | 32 / 60 | 32 | 96 / 24 | > 2500 字 |

### FR-6 AI 排版

接口：`POST /api/ai-format`，入参 `{ text: string }`。

返回：

```json
{
  "title": "大标题，没有可以为空字符串",
  "blocks": [
    { "type": "h2", "text": "小标题" },
    { "type": "p", "text": "正文段落，重点可用 **加粗**" }
  ],
  "density": "loose | standard | compact",
  "notes": "可选：AI 做了哪些判断，一句话",
  "warning": "可选：AI 可能改动了部分原文，请核对"
}
```

约束：

- 文本上限 10000 字，超出返回 413 + 中文提示。
- 超过约 3000 字时按**原有段落边界**切成约 3000 字的块，并行请求后按顺序合并；**只有第一块允许产出大标题**。
- 合并后的 `density` 按合并后总字数按 FR-5 阈值重算，不采信分块之间可能冲突的建议值。
- 限流见 FR-6.1（站点对外开放，接口必须抗刷）。
- API Key 只在服务端使用，绝不出现在前端 bundle、响应体和日志里。
- 错误统一返回 `{ "error": "给用户看的中文说明" }`，前端直接展示。

提示词规则（写在 `lib/ai/format-prompt.ts`，中文，附 1 个「乱文本 → 正确 JSON」短示例）：

1. **不改写原文**。正文必须逐字保留，只允许：合并被错误折断的行、拆分过长段落、删除多余空格/空行/零宽字符、中文语境下半角标点改全角、去掉复制残留（「展开全文」「点击阅读原文」）。不得增删观点、不得润色、不得换词。
2. **分段**：每段约 40–120 字，在句号/问号/感叹号处切分；对话、引语、列举项各自成段；一段只讲一件事。
3. **大标题**：原文第一行像标题就用它；没有则据内容拟一个，≤18 字，口语化、像小红书标题。
4. **小标题**：原文已有「第一/一、/1./【】」结构就提取为 h2；无结构且全文 >600 字时按意思分 2–6 节，每节标题 ≤14 字；<600 字不硬加。
5. **加粗**：每节最多 1–2 处，只加在结论性、金句性短句（≤25 字）上，不整段加粗。
6. **密度**：按排版后总字数给出 `density`。
7. 只输出 JSON，无解释文字，无 markdown 代码块。

原文校验（`lib/ai/validate.ts`）：把原文与 AI 输出（**大标题 + 所有 h2 + 所有 p**）去掉空白、标点和 `**` 后，计算原文字符在输出中的覆盖率。

> 口径修正：原始需求写的是「只比对所有 `p` 文本」，实测会误报——AI 把原文里的「第一件事：别只拍面包」正确地抽成 h2 之后，这些字符就不在 `p` 里了，同一段验收文本的覆盖率从 1.000 掉到 0.861，于是每次正确排版都会弹出「AI 可能改动了原文」。把标题与 h2 一并计入后恢复为 1.000。回归测试见 `tests/validate.test.ts`。

- ≥ 95%：正常返回。
- < 95%：仍返回，附 `warning`，前端用醒目但不吓人的提示条展示。
- JSON 结构非法：重试 1 次，仍失败返回错误。

前端交互：

- 点击后按钮变「排版中…」并禁用，显示进度说明「AI 正在整理段落，长文可能需要 20 秒」。
- 成功：替换文本、自动切到 AI 建议的密度、toast「已排版，可继续修改」。
- 失败：toast 显示接口返回的中文错误，**原文不动**。

### FR-6.1 接口防刷（AI 排版）

站点对外开放且每次排版都要花 AI 调用的钱，`/api/ai-format` 必须按 IP 分层限流。**按顺序检查，任一层不过就直接返回，不再往下走**（越便宜的检查越靠前，被拦的请求几乎不消耗 Redis 命令）：

| # | 层 | 限制 | 超限返回 | 说明 |
|---|---|---|---|---|
| 0 | 入参校验 | 空文本 / >10000 字 | 400 / 413 | 不碰 Redis，最便宜 |
| 1 | 并发锁 | 同一 IP 同时只允许 1 个请求在跑 | 429 上一次排版还没结束，请等它完成 | `SET NX EX 70`，请求结束即释放；单独开锁是因为一次请求可能并行发出多次上游调用 |
| 2 | 突发 | 2 次 / 10 秒 | 429 操作太快了，请过几秒再试 | 真人排版一次要十几秒，这个阈值无感；脚本连点会立刻被挡 |
| 3 | 小时 | 20 次 / 小时 | 429 排版次数达到上限，请一小时后再试 | **按分块数扣额度**（1 万字 = 4 块 = 扣 4 次），防止用超长文本放大上游调用 |
| 4 | 单日 | 50 次 / 天 | 429 今天的排版次数用完了，明天再来 | 挡住「每小时掐着点刷」的慢速消耗 |
| 5 | 全站日预算 | 默认 2000 块 / 天 | 503 今天的 AI 排版额度已用完，请明天再试 | 最后一道闸：有人用代理池换 IP 时，保证 DeepSeek 余额不被刷空 |

补充要求：

- **身份识别**：优先 `req.ip`，回退 `x-forwarded-for` 的第一段；IPv6 按 **/64 前缀**归并，避免同一用户在自己网段内换地址绕过；取不到 IP 时统一归入 `unknown` 桶（天然更严格）。
- **内存短路**：限流器开启 `ephemeralCache`，已判定超限的 IP 在同一实例内直接拒绝，**不再发 Redis 命令**——这是遭到洪水请求时真正起作用的那层。
- **响应头**：超限时返回 `Retry-After`（秒）与 `{ error, retryAfter }`，前端 toast 显示「请 X 秒后再试」。
- **前端配合**：请求期间按钮禁用，返回后再加 10 秒冷却；这只是体验层，不替代服务端限流。
- **降级**：没有 Redis 凭据时退化为进程内计数（单实例内有效，尽力而为），阈值不变。
- **可配置**：阈值全部走环境变量（见第 7 节），改限流不用改代码。
- 失败的请求（上游报错）同样计入额度；这是刻意的——否则可以靠构造失败请求绕过限流。
- **可选加固（本期不做，记在这里）**：Vercel 防火墙按路径限流、同源校验 + 一次性 nonce（挡掉直接拿 curl 打接口的脚本）。

### FR-7 快速清理（规则版，不调 AI）

`lib/cards/clean.ts`，同时作为 AI 排版的服务端预处理：

- 删除零宽字符、`\r`、行首行尾空白，连续空行压成一个。
- 合并硬换行：上一行不以句末标点（`。！？…」"`）结尾、且下一行不像标题时，两行合并。
- 删除中文字符之间的多余空格；中文语境里半角 `, . ; : ? ! ( )` 转全角，**URL、数字小数点、英文句子除外**。
- 超过 150 字的段落在句号处拆开。
- 已有 `#` / `##` 标记原样保留。

### FR-8 健康检查

`GET /api/health` 返回站点与依赖状态：`{ ok, redis: boolean, aiConfigured: boolean, aiKeySource: "env" | "redis" | "none", model }`。**不返回 Key 本身**，最多返回末 4 位用于排查。

## 5. 卡片视觉规格（1080 宽为基准）

| 项 | 值 |
|---|---|
| 背景 | `#FDF9F3` |
| 大标题 | 128px / 行高 170 / 字重 900 / `#84461C`；每行底部一条 `#EFE5DA` 高亮条：从文字中线往下 0.17 字号处开始、高 0.33 字号、宽 = 文字宽 + 0.55 字号，两端对齐的行铺满整行 |
| 小标题 | 70px / 行高 98 / 字重 900 / `#84461C` |
| 正文 | 35px / 行高 70 / 字重 500 / `#8E5D36`；加粗 900 `#76390F` |
| 顶部信息 | 时钟图标 + 「全文X字 ｜ 阅读需要X分钟」，32px / 700 / `#AA8E74`，y=250 |
| 分隔线 | y=300，高 3px，`#E8DED2`，线下留白 70 |
| 左右边距 | 66 |
| 页顶 / 页底留白 | 100 / 110；首页无顶部信息时顶部留白 170 |
| 阅读时长 | 字数 ÷ 450 向上取整，至少 1 |

数值与原型 `C` 对象一致（标题/小标题颜色见下方 D-1 修正）。卡片配色**不随站点深浅色主题变化**。

### 分页规则（沿用原型）

- 小标题必须和后面至少两行正文在同一页。
- 段落首行不单独留在页底（至少带两行，或整段挪到下一页）。
- 中文避头尾：`，。、；：？！）》」』】〕""…—·,.;:?!)%～` 不在行首；`（《「『【〔""(` 不在行尾。
- 非末行两端对齐；字间距 > 0.6 字号时放弃对齐。
- 英文单词与数字（含 `.,:%/'+-` 连接）不拆开。

## 7. 环境变量清单

| 变量 | 必填 | 说明 |
|---|---|---|
| `AI_BASE_URL` | 否 | 默认 `https://api.deepseek.com` |
| `AI_MODEL` | 否 | 默认 `deepseek-flash` |
| `AI_API_KEY` | 否* | 本地开发用；**线上不配**，留给 Redis 托管（见下） |
| `UPSTASH_REDIS_REST_URL` | 是 | `https://ethical-ghoul-90314.upstash.io` |
| `UPSTASH_REDIS_REST_TOKEN` | 是 | Upstash REST Token（待提供） |
| `REDIS_NAMESPACE` | 否 | 默认 `yilin:` |
| `RATE_LIMIT_BURST` | 否 | 突发窗口，默认 `2/10s` |
| `RATE_LIMIT_PER_HOUR` | 否 | 默认 20（按分块数扣额度） |
| `RATE_LIMIT_PER_DAY` | 否 | 默认 50 |
| `AI_DAILY_BUDGET` | 否 | 全站每日分块预算，默认 2000 |

\* `AI_API_KEY` 与 Redis 配置至少有一个可用，否则 AI 排版返回 503「AI 服务未配置」。**读取优先级：环境变量优先，Redis 兜底。** 因此生产环境**不要**在 Vercel 里配 `AI_API_KEY`，这样改 Key 只需改 Redis、不必重新部署；本地开发写 `.env.local` 即可覆盖。

Redis 键（Upstash 只有 0 号库，用前缀隔离，不与 activation-service 的 `code:*` 冲突）：

| 键 | 内容 |
|---|---|
| `yilin:config:ai` | JSON：`{ baseUrl, apiKey, model, updatedAt }` |
| `yilin:rl:burst:<ip>` / `yilin:rl:hour:<ip>` / `yilin:rl:day:<ip>` | `@upstash/ratelimit` 滑动窗口计数（三层） |
| `yilin:lock:ai-format:<ip>` | 并发锁，`SET NX EX 70` |
| `yilin:budget:ai-format:<YYYY-MM-DD>` | 全站当日已消耗的分块数，`INCRBY` + 48h 过期 |

## 8. 原型缺陷修正清单

迁移时必须修掉，不是「保持一致」的范围：

- **D-1（必修）** 原型 `C` 对象里 `title` 和 `h2` 两个键各出现两次：先是颜色字符串 `'#84461C'`，后又被排版参数对象覆盖。结果 `tokenize()` 给标题取到的 `color` 是对象而非颜色字符串，`ctx.fillStyle` 赋值被浏览器忽略，大标题/小标题实际沿用上一次的填充色（高亮条的 `#EFE5DA`）。新实现把颜色与排版参数拆成 `COLORS` 与 `METRICS` 两个对象，标题颜色以第 5 节规格表的 `#84461C` 为准。
  已在浏览器中复现：示例文字的第 1 页大标题呈浅米色（`#EFE5DA`），在 `#FDF9F3` 底上几乎看不见；小标题则沿用了正文色 `#8E5D36` 而非 `#84461C`。
  因此「与原型视觉一致」的验收口径明确为：**分页、断行、间距、高亮条与原型一致，颜色以规格表为准**。
- **D-2** 原型依赖宿主环境的 `window.claude.use('downloads')` 保存文件 → 换成 FR-4 的下载 / 分享方案。
- **D-3** 原型从 `<link>` 直接拉 Google Fonts → 换成 `next/font/google` 自托管。
- **D-4** 原型把全部逻辑写在一个 HTML 里 → 按架构文档拆成可单测的纯 TS 模块。
