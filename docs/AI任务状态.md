## 3. 每一项做了什么、怎么验的

### 2 成本记录（`393464a`，已上线）

此前只有 `ai-format` 调了 `recordUsage()`，三个小红书工具一行成本都没记。

- 按工具分维度：新增 `stats:toolday:<天>`，字段 `工具|指标`
- 精度：原来 `Math.round(cny*100)` 把一次调用（约 ¥0.005–0.015）压成 1 分，
  更便宜的记成 0。新增 `costMicro`（微元）作权威口径，`costFen` **停写**，
  读的时候两段相加 —— 双写同一笔钱才是漏算的根源
- 失败也记账：`AiError` 带上已花的 usage 和 requests；`ai-format` 改用
  `allSettled`，一块失败不会把其它块已付的钱一起扔掉
- `chunks`（内容分块数）和 `requests`（真实上游请求数）分开，前者是历史口径

验证：`tests/cost.test.ts`、`tests/ai-error.test.ts` 共 18 条 + 全量 build。

### 3 合并检查入口（`ee60984`，已上线）

### 6 移动端完整走查（**未上线**）

按 v4.1 §9 的路径在 375×812 真机视口从头走了一遍。

通过的：

| 检查项 | 结果 |
|---|---|
| 三个页面横向溢出 | 都没有 |
| 首页粘贴框 | 343 / 375（两侧 16px 留白），主按钮在首屏内 |
| 检查页「定位」 | 点击后上滚 354px，高亮落在视口内 —— 上下堆叠时视口确实跟过去了 |
| 「继续编辑」返回 | 可达，在视口内 |
| **复制失败回退** | 自动化浏览器无剪贴板权限，**回退提示正确出现，没有假装成功** |
| 固定定位元素 | 只有顶栏 sticky，没有固定底栏 → 键盘不会遮挡操作 |
| 图卡页 | 缩略图（blob）正常渲染，无控制台报错 |
| 控制台 | 三个页面都没有报错 |

修掉的缺陷：

**顶栏在窄屏上溢出边界。** 导航折成两行，但 `.siteHeaderInner` 被
`height: 52px` 钉死，实测第二行链接底部 y=54、顶栏只有 53 —— 挤在边界外，
再加一个工具就会真的溢出。同时触摸目标只有 29px 高。

改成 `min-height`，窄屏加 `flex-wrap` 和上下内边距，链接撑到 40px；
并且**窄屏上不再 sticky** —— 长高之后的 sticky 顶栏会占掉 123px 永久空间，
手机上纵向空间比随手可点的导航更值钱。桌面端实测不受影响（仍是 53px、仍 sticky）。

### 6b 检查 → 图卡 交接（**未上线**）

补上走查时发现缺的那一步。检查页「编辑建议」那组加一个「排成图卡 →」，
图卡页挂载时 `takeHandoff()`。

只有一个按钮，但它总是带**当前最新的那一版**：改写过就带改写后的，
没改写就带输入框里的。放两个按钮（原文 / 改写版）会让人停下来想选哪个。

带过来的内容**优先于图卡页自己的草稿** —— 用户刚点了「排成图卡」，
那就是他现在要排的。但旧草稿会被顶掉，所以要说一声：不弹窗，一句 toast。
交接是用户自己发起的，不该再拦一下。

真机验到的四种情况：

| 情况 | 结果 |
|---|---|
| 有旧草稿 | 提示「已带过来，原来的草稿被替换了」 |
| 没有旧草稿 | 提示「已从发布前检查带过来」 |
| 带了标题 | 自动加 `# ` 大标题标记，省一次手动操作 |
| 没有标题 | 不多塞井号 |

交接后卡片正常渲染、导出按钮在、移动端无横向溢出、无控制台报错。

## 5. 我自己也不确定的地方（审核请优先看这里）

本轮已经被审核抓到过四次错，都是「我声称验过但其实没验」或「改了一半」。
所以这一节如实列出当前最可能有问题的地方：

### 5.1 没有任何生产数据验证过

成本记录、新埋点、`doers` 集合，**全部只在本地内存版 Redis 上跑过**。
生产环境的 Upstash 连上之后行为是否一致，没验证。尤其：

- `doers` 集合每个 (天, 工具, 事件) 一个 key，8 事件 × 5 工具 = 最多 40 个/天。
  Upstash 的命令数和内存成本没估算过
- `recordUsage` 的 `cachedTokens` 依赖上游返回 `prompt_cache_hit_tokens`，
  **没验证过 DeepSeek 实际返回了什么**。如果一直是 0，缓存命中的便宜价没体现

### 5.2 成本是估算，不是账单

单价 `PRICE_USD_PER_M` 和汇率 7.1 是写死的高峰价。和真实账单的差距未知。
失败请求（超时、429）拿不到 token 数，成本记为 0，所以**显示值是下限**。

### 5.3 产品假设全部未验证

- 「发布前检查是值得先试的入口」是判断，不是数据
- 「用户手里已经有东西」（粘贴框的前提）没验证过
- v4.1 §4.3 的频次表整张都是经验估计，没有一行有本站数据支撑

### 5.4 口径引用未逐条核实

v4.1 §2.1 引的两个官方链接（社区公约、蒲公英审核规范）**我没有真打开确认**。
落地前要核实内容和适用范围，尤其蒲公英那份是商业合作报备场景。

### 5.5 图卡交接已补上（原来是方案自身的矛盾）

v4.1 §9 阶段 1 的验收路径里有「带入图卡 → 导出」，但那条链路当时不存在，
而同一份文档 §9 阶段 2 才说要把它串起来 —— 阶段 1 的验收条件写超了。

已经补上（见 §3.6b），所以阶段 1 的验收路径现在能完整走通。
**这等于把阶段 2 的一个条目提前做了**，审核时可以质疑这个取舍。

### 5.7 触摸目标普遍是 40px，不是 44px

按钮统一 40px 高（iOS 人机界面指南建议 44）。导航链接已经从 29px 提到 40px。
40px 在实践中可用，但没有达到指南值，也没有做过真机手指测试 ——
这里全部是视口模拟，**不是真手机**。
